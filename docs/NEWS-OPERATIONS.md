# Janet 晨报与站点建设 · 2026-11-10

本次交付包括新闻采集台、来源目录、云端线索采集、线上发布巡检、归档阅读层级及正文导航。采编保持 5-4-4-3-1 共17条，全文语音紧跟每条新闻和锐评。线索采集与编辑发布分开，采集不会自行凑数或发布。

## 日常顺序

1. `node codex-briefing-system/src/inspect-live-briefing.mjs YYYY-MM-DD` 先查线上。`published`时结束；`check_failed`先处理连接问题；`audio_incomplete`只补语音；部署不完整时修缺失文件。
2. 当期确实缺失时，运行任务准备脚本，读取编辑规范、最近五期与采集板；本机可运行 `node codex-briefing-system/src/collect-candidates.mjs YYYY-MM-DD` 刷新线索。
3. 原文核验：发布时间不能用更新/转载时间替代；仅日期或午夜占位要补官方发布帖、仓库提交等证据。微调、转换、作者自报、旧事件的新分析逐项标注。链接去重之外还要编辑判断同一事件。
4. 先写 editorial-plan，再写17条 content；每条配对应原图与来源，生成21:9封面。
5. 后处理生成完整语音，检查17条标题、正文和锐评以及20个章节，之后才同步并提交。SSH失败沿用已授权连接器，以远端当前SHA安全更新，保留远端其他文件。
6. 等部署成功，再运行 `node codex-briefing-system/src/finalize-publication.mjs YYYY-MM-DD`；只有 `publication-receipt.json` 为 `verified` 才报告完整发布。部署回调也会自动执行相同校验并保留报告。只读巡检不得重复触发订阅邮件。采集快照由网页直接读取，避免另起整站部署；部署不主动取消正在发布的晨报，保留 Briefing 标题的邮件联动。只有公共网页、样式、脚本、数据或打包脚本变化才自动部署；采编检查器与流程文档修改由独立验证工作流检查，不重复发布近1GB站点，发布配置保留手动触发入口。发布包按运行ID和尝试次数独立命名，避免任务重试时出现多份同名包而部署失败。

## 渠道使用规则

- 官方公司页和版本记录：确认“已经发布/预览/计划”、地区与资格，不由模型名称推断访问权限。
- 研究、论文与数据集：作者身份、初稿与新版本分开；内部自测、预印本、独立复现与同行评审分开。
- 投融资与财报：优先公司、投资人、监管披露；本轮与累计、股权与额度、收入运行率与实际收入分开。
- 媒体和中文渠道：承担发现与语境补充，融资金额、参数与时间回到原文。付费摘要不扩写为不存在的完整报道。
- 图片：优先事件原图、官方产品示例或原始文档，保留图注；不拿媒体默认横幅或无关Logo顶替。自动采集的线索目前不声称已经核验图片。

## 开发与发布验证

发布副本整理只处理有结构化正文及HTML的历史新闻目录；任何页面、JSON、脚本、样式、字幕或SVG中出现过文件名就保留，缺少完整来源的旧刊全部保留。不会改正文、图片内容或语音源哈希，且不删除仓库原件。报告保存在打包目录外的 `*.pruned-images.json`。

[GitHub Pages 官方容量与10分钟部署限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)。

核心回归：`node --test codex-briefing-system/src/news-desk.test.mjs codex-briefing-system/src/briefing-run-state.test.mjs codex-briefing-system/src/finalize-publication.test.mjs codex-briefing-system/src/narration.test.mjs codex-briefing-system/src/editorial-qa.test.mjs scripts/prune-news-image-copies.test.mjs`。

旧的 `npm run publish` 入口已统一到完整后处理，重新渲染并执行图片、正文、语音门禁；推送后只报告待验证，不再冒充已上线。`npm run verify -- YYYY-MM-DD` 生成自动回执。

正文与语音检查分别运行 `qa-briefing.mjs`、`qa-narration.mjs`。Pages打包必须显式包含两份采集数据，远端完整仓库构建后运行 `qa-current-site.mjs`。局部稀疏工作区不能代替完整部署构建。

采集与巡检采用精简检出，只下载执行代码和采集目录；不拉取约1GB的作品视频与历史配图。仅正式发布需要完整仓库与整站打包。

公开页面只展示公共来源、候选标题及已发布内容，不暴露密钥、私有编辑档案或本地运行记录。网页没有冒充多人共享的编辑后台：当前为只读工作台，可导出线索，正式编辑仍经仓库发布流程。
